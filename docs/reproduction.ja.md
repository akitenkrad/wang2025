# 再現

## 一括再現 — `reproduce` (推奨)

`reproduce` サブコマンドは付録 F / Table 7-2 の 4 条件を 1 コマンドで実行し (古典 `--provider none`・オフライン・LLM 呼び出し 0)，条件ごとの PASS/off 判定付きの観測 vs 論文サマリを書き出す:

```bash
cargo run --release -- reproduce --runs 30 --seed 42   # → results/culture-llm/reproduce_<run_slug>/
uv run culture-llm-tools reproduce --runs 30 --seed 42 # 同上 + 観測 vs 論文の図
uv run culture-llm-tools reproduce --quick             # 高速エンドツーエンドスモーク
```

条件はそれぞれ子 run (`subcommand=reproduce-condition`) になる．観測値 (`mean_n_stable_regions`, `mean_lc`, `mean_gp`, `mean_gp_per_agent`, `converged_fraction`, `n_units`) はその `metrics.csv`，Axelrod の報告値は出典つきで `reference.csv`，個々の試行は `events.jsonl` の `terminal` 行にある．許容幅と PASS/off の判定は**論文のものではなくこちらが置いたもの**なので，指標にも報告値にも混ぜず，親の `artifacts/reproduce_verdicts.csv` とコンソールに残す．

## 古典ベースライン — Axelrod Table 7-2 (定量)

古典プロバイダ (`--provider none`・LLM 不使用) は Axelrod (1997) Table 7-2 を再現する: 10×10 グリッドにおける安定文化地域数の平均．個別条件は手動でも `--runs 30` で実行できる:

```bash
cargo run --release -- run --provider none --width 10 --height 10 --features 5  --traits 10 --runs 30 --seed 42
cargo run --release -- run --provider none --width 10 --height 10 --features 5  --traits 15 --runs 30 --seed 42
cargo run --release -- run --provider none --width 10 --height 10 --features 10 --traits 10 --runs 30 --seed 42
cargo run --release -- run --provider none --width 10 --height 10 --features 15 --traits 15 --runs 30 --seed 42
```

測定した `mean n_stable_regions` (本実装・`--runs 30`・seed 42):

| F | q | Axelrod 目標 | 測定値 | 許容内? |
|---|---|----------------|----------|-------------------|
| 5 | 10 | 3.2 (±0.5) | 約 5.2 | やや高い — 姉妹 `axelrod1997` (≈4.8) と整合．注記参照 |
| 5 | 15 | 20.0 (±3.0) | 約 19.1 | 可 |
| 10 | 10 | 1.0 (±0.3) | 1.0 | 可 (一致) |
| 15 | 15 | 1.2 (±0.3) | 1.0 | 可 |

Axelrod の定性的符号は成立する: `F` 増加で安定地域減少，`q` 増加で増加．F5q10 は公表値 3.2 をやや上回るが，同条件で姉妹 `axelrod1997` も ≈4.8 を出すため，これは RNG/平均化の性質 (Axelrod 原典の Monte-Carlo 設定が異なる) であり本移植固有の問題ではない．他の 3 条件は許容内である．

> 古典経路は LLM 呼び出し **0 回**．呼び出しが無い run には `llm_calls` の行も `llm` ブロックも書かない — 0 を書くのではなく «無い»．分母 0 の cache-hit 率は定義できないためである．

## LLM 変種 — 付録 F LC/GP (定性)

LLM プロバイダは論文付録 F の振る舞いを定性的に再現する (ローカル既定 `llama3.2` は論文モデルと異なるため数値完全一致は目標としない):

- LC はラウンドにわたり上昇し 0.50 を超える (論文は round 60 までと記載)．
- 古典変種と同じモノカルチャ⇄ポリカルチャ転移．

```bash
OLLAMA_MODEL=llama3.2:latest cargo run --release -- run --provider ollama --width 5 --height 2 --features 5 --traits 5 --rounds 100 --seed 42
uv run culture-llm-tools visualize
```

## 古典 vs LLM — `compare`

`compare` サブコマンドは古典ベースラインと LLM 変種を一致条件 (同一グリッド / シード / ラウンド) で実行し，親 run 1 本 + 片側ごとの子 run にする．各側の LC / GP / regions / 収束はそれぞれの子 (`subcommand=compare-side`)，差は親の `scope=sweep` 指標にある．`--mock` で決定論的スクリプト LLM クライアントを使うと比較全体がオフラインで完結する．古典側は常に実行 (LLM 呼び出し 0):

```bash
# オフライン: 古典は実行・LLM は構造的 (スクリプト mock)
cargo run --release -- compare --mock --features 5 --traits 5 --rounds 100 --seed 42
uv run culture-llm-tools compare-report

# 実 LLM (到達可能なバックエンドが必要)
OLLAMA_MODEL=llama3.2:latest cargo run --release -- compare --llm-provider ollama --rounds 100 --seed 42
```

### GP 目標と文書化された不一致

付録 F は `GP ≈ 0.35–0.40` を報告するが，文書記載の式 `GP = |C| / N²` は `1/N` で上限されその帯に到達できない．本実装は `gp = |C| / N²` (文書) と `gp_per_agent = |C| / N` (補助) の両方を記録する．後者が論文の帯に整合しうる正規化である．[アーキテクチャ](architecture.ja.md#gp-の不一致-重要) を参照．
